## Decisions

### No new architectural decisions this session

Both 7b review fixes and 7c migration document executed existing plans and
reconciliation decisions. The session's value was in verification precision,
not new architecture. The scrutiny rounds corrected factual claims against
live source — these were accuracy fixes, not design choices.

### "Functional replacement" over "Full parity" in parity matrix wording

**Choice:** Downgrade all parity status entries from "Full parity" to
"Functional replacement" with specific qualifiers (flags dropped, data
model changed, lifecycle changed, scouting model changed).

**Driver:** User scrutiny round 1 identified that claiming "full parity"
for workflows with material differences (consult drops flags, dialogue
drops `--profile`/`--plan`, delegate changes lifecycle, analytics changes
data model) was over-smoothing that could mislead downstream slices.

**Alternatives considered:**
- **Keep "Full parity"** — rejected because it collapses important
  differences that 7d/7e must preserve during removal.
- **Per-cell qualification** — too verbose for a matrix row; qualifier
  goes in the migration guide section instead.

**Trade-offs accepted:** "Functional replacement" is less reassuring than
"Full parity" but is honest about architectural differences.

**Confidence:** High (E2) — verified each workflow's actual flag/lifecycle
differences against live skill frontmatter and server source.

**Reversibility:** High — wording change in a doc.

**Change trigger:** If someone demonstrates exact API/flag compatibility
that the current wording understates.

### Dialogue scouting described as three-phase Claude-side, not "pre-dialogue only"

**Choice:** Describe codex-collaboration's dialogue scouting as three
phases: (1) pre-dialogue gatherers, (2) Phase 1 bounded inline scouting,
(3) Phase 3 per-turn verification scouting.

**Driver:** User scrutiny found that the draft said "pre-dialogue evidence
gathering only" and "no mid-conversation injection" — materially false
against live source. `dialogue-orchestrator.md` Phase 1 (line 60) performs
bounded inline scouting and Phase 3 Step 5 (line 108) performs per-turn
verification scouting.

**Alternatives considered:**
- **Keep "pre-dialogue only"** — rejected because it's factually wrong.
- **Say "context-injection retired, no scouting replacement"** — also
  wrong; scouting capability was reimplemented, just not via MCP.

**Trade-offs accepted:** The description is now longer and more nuanced.
Worth it for accuracy.

**Confidence:** High (E2) — verified against `dialogue-orchestrator.md`
lines 60, 72, 100, 108.

**Reversibility:** High — wording change.

**Change trigger:** If the dialogue-orchestrator's scouting phases change.

are accepted trade-offs.

## Learnings

### Scrutiny rounds catch factual errors invisible to structural review

**Mechanism:** The code-reviewer and comment-analyzer agents found
structural and consistency issues (missing table rows, divergent templates).
The user's manual scrutiny found factual errors against live source
(wrong scouting model, wrong analytics claim, wrong transport). These two
review types are complementary — structural review catches form issues,
scrutiny catches truth issues.

**Evidence:** PR #117 review found 2 critical + 6 improvement items (all
structural). 7c scrutiny round 1 found 3 high-severity factual errors that
no automated review would catch — they required reading `dialogue-orchestrator.md`,
`codex-reviewer.md`, and `runtime.py` and comparing against the draft's claims.

**Implication:** For documentation artifacts that make claims about system
behavior, automated review is necessary but not sufficient. Manual scrutiny
against live source is the truth check.

### Over-smoothing is the primary failure mode in cutover documentation

**Mechanism:** Migration documents try to make replacement relationships
clean. "Full parity" is more comforting than "functional replacement with
differences." One-line transport descriptions hide architectural shifts.
The smoothing makes the doc feel complete while hiding the differences that
downstream slices must preserve.

**Evidence:** All 3 high-severity errors in 7c round 1 were over-smoothing:
(1) collapsing three scouting phases into "pre-dialogue only," (2) erasing
cross-model review analytics to sharpen the "new analytics" narrative,
(3) describing `codex exec` transport when the actual path is App Server
JSON-RPC.

**Implication:** Future cutover/migration docs should be scrutinized
specifically for over-smoothing. The test: "Would a remover using this doc
make a mistake?" If a 7e remover read "no mid-conversation injection" and
deleted context-injection, they'd lose the retirement rationale that
preserves the scouting *capability*.

### Closeout notes are cheap insurance for traceability

**Mechanism:** Each merged slice gets a separate closeout PR that checks
the AC checkbox and cites PR, merge commit, and evidence. The closeout is
1 file, 1 commit, <5 minutes.

**Evidence:** This session created 3 closeout PRs (#118, #119, #121) in
~15 minutes total. Each provides a direct link from the ticket AC to the
implementation evidence. Without them, a governance reviewer would need to
trace PR #117 → branch → diff → smoke evidence manually.

**Implication:** Continue the closeout-PR pattern for 7d and 7e.
