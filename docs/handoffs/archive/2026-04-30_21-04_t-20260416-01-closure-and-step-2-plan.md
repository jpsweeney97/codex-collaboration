## Learnings

### Self-referential closure criteria create unfillable checkboxes

**Mechanism:** A closure criterion that says "record the final commit SHA" cannot be honestly checked before the commit that records it exists. Checking it before the commit is dishonest; leaving it unchecked after the commit requires an amendment.

**Evidence:** P3 finding during user review (confidence 0.78). The checkbox said "Update this ticket with final commit SHA and mark `status: closed`" — but the closure section only recorded the implementation commit (`00ec0054`), and the closeout commit hadn't been made yet.

**Implication:** Anchor closure criteria to existing, concrete artifacts (like the implementation commit SHA) rather than to the closeout commit's own SHA. The criterion should describe what was done, not what the criterion itself is doing.

**Watch for:** Any future ticket with a closure checkbox that references the commit performing the closure.

### Status-surface consistency requires sweeping all reader entry points

**Mechanism:** Closing a ticket and updating the register is necessary but not sufficient. The `codex-collaboration-current-state.md` is the canonical reader entry point, and its watchpoint list must also be updated. Stale watchpoints in current-state send the next executor into closed tickets.

**Evidence:** P2 finding during user review (confidence 0.91). After closing T-20260416-01, the current-state doc still listed it as an active watchpoint.

**Implication:** Ticket closure is a 3-surface operation: (1) ticket itself, (2) register row, (3) current-state watchpoint. Missing any one creates drift.

**Watch for:** Any future ticket closure — check all three surfaces.

### `~/.agents/` has a simpler security profile than `~/.codex/`

**Mechanism:** Unlike `~/.codex/` which mixes credential files (0600 mode) with benign data, `~/.agents/` is purely configuration and skill content. All world-readable, no subdirectory-level carve-out needed.

**Evidence:** `find ~/.agents/ -maxdepth 3` showed only `plugins/marketplace.json` and `skills/*/SKILL.md` type content. No `auth.*`, `config.*`, `*.sqlite`, or session files.

**Implication:** New `readableRoots` categories should be assessed for credential-class files before deciding between full-directory and subdirectory-level carve-outs.

**Watch for:** If `~/.agents/` gains credential files in the future.

## Gotchas

### Ticket closure is a 3-surface operation

Closing a codex-collaboration ticket requires updating three surfaces: (1) the ticket itself (`status: closed`, move to `closed-tickets/`), (2) the reconciliation register (remove row, renumber priorities), (3) the current-state document (remove watchpoint). The P2 finding this session confirmed that missing the current-state watchpoint creates drift visible to the next executor.

### `git mv` is not needed for ticket moves

`git add` on both the old (deleted) and new (untracked) paths lets git auto-detect the rename via content similarity. The closure commit showed `rename docs/tickets/{ => closed-tickets}/...md (86%)` — git recognized the move despite the added Closure section reducing similarity from 100%.

### Worktree `.git` file is a text file, not a directory

In git worktrees, `.git` is a *file* containing `gitdir: <path>`, not a directory. The gitdir resolution for Option E must check `is_file()`, not `is_dir()` or `exists()`. A regular git repo root has a `.git` *directory* — the resolution must handle both cases gracefully.

### Self-referential closure criteria

A closure checkbox that says "record the final commit SHA" creates a paradox: the SHA doesn't exist until the commit, but the commit includes the checked box. Anchor criteria to existing artifacts (implementation commit SHA) rather than the closeout commit's own SHA.
