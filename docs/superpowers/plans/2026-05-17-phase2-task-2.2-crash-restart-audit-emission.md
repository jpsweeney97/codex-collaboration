# Phase 2 Task 2.2 — Contract-Valid Crash/Restart Audit Emission — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emit contract-valid `crash`/`restart` `AuditEvent`s from startup recovery for the three recovery subjects (`lineage_handle`, `orphaned_active_job`, `operation_journal`) with persisted `(action, recovery_key)` deduplication, without any `AuditEvent` schema change or contract growth.

**Architecture:** A single journal-owned dedup primitive (`OperationJournal.append_recovery_audit_event_once`) backed by a dedicated persisted seen-set. `DialogueController` emits `lineage_handle` events at its two reattach loci (phase-1 `_recover_thread_creation:dispatched`; phase-2 `recover_startup` reattach/quarantine), staging the `turn_dispatch` driving-entry metadata in an in-memory same-pass dict. `DelegationController` emits `operation_journal` crash on **durable** journal reconciles — `job_creation`/`approval_resolution` `dispatched`-gated (residual-proof: the unresolved `dispatched` entry *is* the interruption evidence; their `:intent` is journaled strictly before the side effect, a pure no-op), `promotion` gated on a recovery-pass-local durable-mutation predicate (`promotion_reconciled` — *both* phases have no-op sub-paths; design Oracle 4 amended, see Task 2.2.3's *Authority reconciliation* note and `recovery-and-journal.md` §Crash precondition, "recovery-outcome, not phase") — and `orphaned_active_job` crash on the orphan sweep. `McpServer` is unchanged in behavior; a wiring test proves the eager/lazy paths cannot double-emit (persisted dedup spans process+disk).

**Tech Stack:** Python 3.11+, pytest, ruff. JSONL audit log at `${plugin_data}/audit/events.jsonl`. No new dependencies.

## Hard Constraints (from the design — non-negotiable)

1. **No `AuditEvent` schema change.** `action` is an unconstrained `str`; `extra` already exists (`server/models.py:201-217`). Do not add fields to any dataclass in `server/models.py`.
2. **No contract growth.** The `extra` sub-contract keys are exactly: mandatory `recovery_key`, `recovery_subject`, `recovery_result`, `detected_during`; conditional `recovery_operation`, `recovery_phase`; `restart`-only `crash_recovery_key`. Do not invent keys (no key for the phase-1 turn confirm/quarantine sub-state).
3. **`recovery_operation`/`recovery_phase` stay Conditional** — present **iff** a driving `OperationJournalEntry` exists. For `turn_dispatch` they come from **in-memory same-pass** staging (best-effort); a second crash before the phase-2 audit append legitimately degrades the event to the between-turn shape (oracle 12 — keys absent). Tests assert these keys only **within one recovery pass**, never across a retry.
4. **`lineage_handle` stem keys on `collaboration_id`, never `runtime_id`** (reattach mutates `runtime_id`). Load-bearing for persisted dedup.
5. **Emit only after the item's reconciliation write succeeds.** A failure before that write emits nothing and never a false successful `restart`.
6. **Sentinel `runtime_id="recovery:unknown-runtime"`** appears iff `action="crash"` AND `detected_during="startup_recovery"` AND no runtime was ever recorded — exactly (a) `operation_journal` entry with no `runtime_id`, or (b) `lineage_handle` created during recovery from a runtime-less `thread_creation:dispatched` entry. Never on `restart`, never on `orphaned_active_job`, never on a pre-existing `lineage_handle`.
7. **Recovery audit emission is best-effort and isolated.** The emit helpers (`_emit_lineage_handle_recovery`, `_emit_operation_journal_crash`, `_emit_orphaned_active_job_crash`) MUST log-and-swallow any `append_recovery_audit_event_once` failure. A failed append degrades to an **absent** record (§Durability); it MUST NOT propagate into a recovery loop's broad `except`, mutate a handle/job status, or fabricate a `*_quarantined_unknown`/failed outcome. This is the post-reconcile mirror of constraint 5 (which covers the pre-reconcile direction).

## Locked-Behavior Note (P1 — adversarial-review reconciliation)

This plan was adversarially reviewed. One finding (**P1**) argued the crash-after-reattach / before-audit window writes a "materially wrong forensic record" and proposed durable staging or an ordering change. That window and its accepted outcome are **locked design**, not a plan defect:

- Design **§Durability** explicitly accepts that a second crash between phase-1's durable journal finalize and the phase-2 audit append degrades the event to the **between-turn shape (oracle 12)**, and explicitly **rejects durable staging** ("Durable staging is **not** adopted … against this section's stance"). This was resolved in round-11 (HEAD `83b2145`).
- Design **§Emission ordering** mandates mutate-then-emit (constraint 5); the review's "change ordering" alternative would reverse it and reintroduce the false-successful-`restart` hazard oracle 7 guards.
- **Do NOT reopen §Durability or §Emission ordering in this plan.** The P1 disposition is *coverage for locked behavior*, not a blocker.

The valid, in-scope residue is one missing test (added in Sub-step C):

- A **degradation-sequence test** proving a second crash after phase-1 journal finalization and before phase-2 audit completion produces the **oracle-12 between-turn shape** — contract-valid, `crash_recovery_key` resolves, no duplicate, no false standalone `restart`.
- It models **persisted post-process-death state** (a fresh stack re-running recovery with the driving entry already finalized/trimmed and no audit record) — **never** an `append_*` exception. (Append-exception isolation is a *separate* concern: constraint 7 + its own test, not the durability window.)
- It asserts **contract-valid degradation, not original-runtime fidelity**. The accepted §Durability tradeoff is precisely the **op/phase loss** (`recovery_operation`/`recovery_phase` absent once the driving entry is trimmed) — *not* a runtime change. The surviving `crash` carries the handle's pre-existing real `runtime_id` at enumeration (the normal oracle-12 identity rule, model-guaranteed non-sentinel; in the test, the original `rt-sess-1`, asserted precisely). The test makes no original-failed-runtime fidelity claim and no runtime-degradation claim — there is no runtime mutation in this window (phase-1 finalize never calls `update_runtime`).

def _populate_from_recovery_audit_record(
    record: dict[str, Any],
    recovery_seen: set[_RecoveryAuditDedupKey],
) -> None:
    action = record.get("action")
    if action not in ("crash", "restart"):
        return
    extra = record.get("extra")
    if not isinstance(extra, dict):
        return
    recovery_key = extra.get("recovery_key")
    if not isinstance(recovery_key, str):
        return
    recovery_seen.add((action, recovery_key))

    def append_recovery_audit_event_once(
        self, event: AuditEvent, *, recovery_key: str
    ) -> bool:
        """Append a recovery audit event unless (action, recovery_key) exists.

        Dedupes against both in-memory state and persisted audit/events.jsonl.
        Returns True when appended, False when a duplicate was suppressed.
        Fails fast if event.extra['recovery_key'] disagrees with recovery_key.
        """

        event_recovery_key = event.extra.get("recovery_key")
        if event_recovery_key != recovery_key:
            raise ValueError(
                "append_recovery_audit_event_once failed: "
                "event.extra['recovery_key'] disagrees with recovery_key argument. "
                f"Got: {event_recovery_key!r:.100}"
            )
        self._ensure_recovery_audit_seen_loaded()
        key: _RecoveryAuditDedupKey = (event.action, recovery_key)
        if key in self._recovery_audit_seen:
            return False
        self.append_audit_event(event)
        self._recovery_audit_seen.add(key)
        return True
```

### Sub-step 0 (prerequisite) — Test harness: injectable runtime identity

`ControlPlane` caches the advisory runtime in-process (`server/control_plane.py:367,484-489` — a second `get_advisory_runtime` returns the cached runtime without minting a new id). So a test that calls `controller.start()` then `controller.recover_startup()` on the **same** controller does **not** model a post-crash restart: the "resumed" runtime is the same id as the crash runtime, and the design's "`restart` carries a **new** runtime" requirement (oracle 2/9/11/12) plus the `collaboration_id`-stable-vs-`runtime_id`-keyed-stem invariant (oracle 6, constraint 4) would be asserted vacuously. The fix is structural: model a fresh post-crash process as a **second stack over the same `tmp_path`/`session_id`** with a different runtime identity. `_build_dialogue_stack` cannot express that today (it hard-codes `rt-{session_id}` and ties runtime identity to `session_id`, but `session_id` also keys the lineage/turn stores, so it cannot simply be varied). Add an optional `runtime_prefix`.

def _build_dialogue_stack(
    tmp_path: Path,
    *,
    session: FakeRuntimeSession | None = None,
    session_id: str = "sess-1",
    runtime_prefix: str = "rt",
) -> tuple[DialogueController, ControlPlane, LineageStore, OperationJournal, TurnStore]:
    """Wire up a full dialogue stack with test doubles.

    runtime_prefix controls the advisory runtime id minted by this stack's
    ControlPlane. Default "rt" yields the exact pre-plan sequence —
    "rt-{session_id}" then bare "uuid-{i}" — so every existing assertion and
    every later-id consumer is preserved bit-for-bit. Build a SECOND stack over the same tmp_path/session_id
    with a different runtime_prefix to model a fresh post-crash process: the
    persisted lineage/journal/audit state is shared, but a reattach mints a
    genuinely new runtime id (ControlPlane caches runtime in-process, so the
    same stack cannot). collaboration_id stays session-keyed (stable) — it is
    the lineage_handle dedup stem and must not vary across recovery passes.
    """
    session = session or FakeRuntimeSession()
    plugin_data = tmp_path / "plugin-data"
    journal = OperationJournal(plugin_data)
    plane = ControlPlane(
        plugin_data_path=plugin_data,
        runtime_factory=lambda _repo_root: session,
        compat_checker=_compat_result,
        repo_identity_loader=_repo_identity,
        clock=lambda: 100.0,
        uuid_factory=iter(
            (
                f"{runtime_prefix}-{session_id}",
                *(
                    f"uuid-{i}"
                    if runtime_prefix == "rt"
                    else f"{runtime_prefix}-uuid-{i}"
                    for i in range(100)
                ),
            )
        ).__next__,
        journal=journal,
    )
    store = LineageStore(plugin_data, session_id)
    turn_store = TurnStore(plugin_data, session_id)
    controller = DialogueController(
        control_plane=plane,
        lineage_store=store,
        journal=journal,
        session_id=session_id,
        repo_identity_loader=_repo_identity,
        uuid_factory=iter(
            (f"collab-{session_id}", *(f"id-{i}" for i in range(100)))
        ).__next__,
        turn_store=turn_store,
    )
    return controller, plane, store, journal, turn_store
```

Only the `ControlPlane` runtime `uuid_factory` gains the prefix; the controller's `collab-{session_id}` factory is unchanged (collaboration_id is the dedup stem — it MUST stay stable across recovery passes). The tail is **bare `uuid-{i}` for the default** and `{prefix}-uuid-{i}` only for a non-default stack; that conditional is load-bearing — it makes the default sequence (`rt-{session_id}`, `uuid-0`, `uuid-1`, …) **bit-identical** to the pre-plan helper (`tests/test_dialogue.py:42-44`), so `runtime_prefix="rt"` reproduces the prior ids exactly and no existing test changes behavior. Do **not** collapse it to an unconditional `{prefix}-uuid-{i}` tail — that would silently renumber every default stack's later runtime ids (a hidden-test trap, even though no current visible assertion reads past the first id). A non-default stack (e.g. `rt1`) gets fully distinct ids end-to-end, so a second post-crash stack's reattach mints a genuinely new runtime even if the tail is consumed.

    def _emit_lineage_handle_recovery(
        self,
        *,
        collaboration_id: str,
        crash_runtime_id: str,
        restart_runtime_id: str | None,
        recovery_result: str,
        recovery_operation: str | None,
        recovery_phase: str | None,

        """Emit lineage_handle crash (+restart on reattach success).

        Caller MUST invoke this only after the item's reconciliation write
        (update_runtime on success, update_status('unknown') on quarantine)
        has succeeded — design §Emission ordering. restart_runtime_id is None
        for the quarantine path (crash only). The stem keys on
        collaboration_id, never runtime_id (design constraint 4).

        Best-effort and isolated (constraint 7): an audit-append failure is
        logged and swallowed, never raised. This method runs INSIDE
        recover_startup's broad per-handle try/except; an escaping exception
        would be misread as a reattach failure and flip a successfully
        reattached handle to "unknown" while emitting a false
        handle_quarantined_unknown crash. Per design §Durability the audit log
        is best-effort append: a failed append may only LOSE the record, never
        change the reconcile outcome. The oracle-8 fail-fast (recovery_key
        disagreement) cannot arise here — this method sets
        extra["recovery_key"] == the recovery_key argument by construction;
        oracle 8 is exercised directly at the journal in test_journal.py.
        """

        crash_key = f"{stem}:crash"
        crash_extra: dict[str, object] = {
            "recovery_key": crash_key,
            "recovery_subject": "lineage_handle",
            "recovery_result": recovery_result,
            "detected_during": "startup_recovery",
        }
        if recovery_operation is not None:
            crash_extra["recovery_operation"] = recovery_operation
        if recovery_phase is not None:
            crash_extra["recovery_phase"] = recovery_phase
        restart_key = f"{stem}:restart"
        try:
            self._journal.append_recovery_audit_event_once(
                AuditEvent(
                    event_id=self._uuid_factory(),
                    timestamp=self._journal.timestamp(),
                    actor="system",
                    action="crash",
                    collaboration_id=collaboration_id,
                    runtime_id=crash_runtime_id,
                    extra=crash_extra,
                ),
                recovery_key=crash_key,
            )
            if restart_runtime_id is None:
                return
            restart_extra: dict[str, object] = {
                "recovery_key": restart_key,
                "recovery_subject": "lineage_handle",
                "recovery_result": recovery_result,
                "detected_during": "startup_recovery",
                "crash_recovery_key": crash_key,
            }
            if recovery_operation is not None:
                restart_extra["recovery_operation"] = recovery_operation
            if recovery_phase is not None:

            self._journal.append_recovery_audit_event_once(
                AuditEvent(
                    event_id=self._uuid_factory(),
                    timestamp=self._journal.timestamp(),
                    actor="system",
                    action="restart",
                    collaboration_id=collaboration_id,
                    runtime_id=restart_runtime_id,
                    extra=restart_extra,
                ),
                recovery_key=restart_key,
            )

            # Swallow so the enclosing recover_startup broad except cannot
            # convert a successful reattach into a false quarantine

    audit_path = plugin_data / "audit" / "events.jsonl"
